# Hailo-8 Compilation Guide (Obstacle Detection)

This module handles the transformation of a trained YOLO26 model from ONNX format to a **Hailo Executable Format (`.hef`)**, optimized for the Hailo-8 NPU.

## Prerequisites

* **Git LFS:** Install `git-lfs` and run `git lfs install` once in this repository before fetching the compiler package.
* **Hailo Dataflow Compiler:** Fetch the `.whl` installer with `git lfs pull` so the file in `obstacle-detection/` is the actual wheel, not a pointer text file.
* **Docker:** Recommended for all platforms to ensure environment consistency.
* **ONNX Model:** A trained model (e.g., `best.onnx`) generated by the training module.

If you want to confirm the wheel was fetched correctly, run:

```bash
file hailo_dataflow_compiler-3.28.0-py3-none-linux_x86_64.whl
```

The output should report a Zip archive. If it still says ASCII text, the LFS content has not been downloaded yet.

---

## Pipeline Overview

### 1. Parsing

The `HailoCompiler.parse()` method translates the ONNX computational graph into Hailo's Internal Representation (HAR), then loads `inference/optimize.alls`.

* **Targeting:** It targets the detection heads configured in `HailoConfig.END_NODE_NAMES`.
* **Optimization:** This stage ensures the NPU hardware can execute the convolutional layers efficiently.

### 2. Quantization (INT8)

`HailoCompiler.optimize()` converts the model weights from 32-bit floats to 8-bit integers.

* **Calibration:** Uses up to 512 images (`HailoConfig.CALIB_COUNT`) from the configured calibration directories.
* **Pre-processing:** Images are resized to $640 \times 640$ and kept in `[0,255]`; normalization is applied by `optimize.alls` (`normalization(..., [255,255,255])`).

### 3. Compilation

`HailoCompiler.compile()` invokes the back-end compiler to generate the binary `.hef` file tailored for the Hailo-8 architecture.

## How to Run

### Option A: Via Docker (Recommended)
Since the Hailo SDK is only compatible with Linux x86_64, use the provided Docker wrapper from the `obstacle-detection` root:

```bash
# Basic run (uses default paths in hailo_config.py)
./run_docker.sh

# Dynamic run (specify your specific training run)
./run_docker.sh --onnx train/runs/detect/yolo26_obstacle/weights/best.onnx

```

### Option B: Native Execution (Linux only)

If you have the Hailo SDK installed in a local `venv`:

```bash
python3 inference/compile.py --run --onnx train/runs/detect/yolo26_obstacle/weights/best.onnx

```

## Troubleshooting & Tips

* **Wheel Is a Pointer File:** If `file hailo_dataflow_compiler-3.28.0-py3-none-linux_x86_64.whl` reports ASCII text, install `git-lfs`, run `git lfs install`, then run `git lfs pull` from the repository root and verify again.
* **Path Not Found:** If the script can't find your model, verify the path relative to the root. The Docker container maps the current directory to `/workspace`.
* **macOS (M3) Performance:** Running via Docker on Apple Silicon uses **x86_64 emulation**. The building process and quantization might take several minutes—this is normal.
* **Memory Issues:** Ensure Docker has at least **8GB of RAM** allocated, as the Hailo optimization process is memory-intensive.
